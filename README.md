## 서비스 소개

경매 물건의 가격을 이해하려면 입찰 정보뿐 아니라 주변 거래와 건물 정보를 함께 확인해야 합니다. Rising Home은 법원 경매·온비드 공매와 실거래 데이터를 지도와 상세 패널로 연결합니다. 관심 물건을 저장하고 다시 찾아보는 흐름도 제공합니다.

| 핵심 범위 | 공공 데이터 수집·정규화, 지도 조회, 경매·공매 상세, 실거래 비교 |
| 이 저장소 | 서비스와 개인 기여를 소개하는 포트폴리오 문서 |

## 주요 기능

### 지도에서 경매·공매 탐색

지역과 조건을 바꾸며 물건을 탐색하고, 단지를 선택해 경매·공매 목록과 상세 정보를 확인합니다. 상세에서는 가격, 일정, 사진과 문서를 살펴볼 수 있습니다.

### 실거래가 조회와 비교

매매·전월세, 주택 유형, 가격·면적 조건으로 거래를 조회합니다. 단지 상세와 면적별 거래 내역을 통해 물건의 가격을 비교할 수 있습니다.

### 관심 목록과 서비스 운영

관심 거래·경매를 저장하고 마이페이지에서 관리합니다. 공지, 뉴스, 문의·관리자 기능과 감정평가서 기반 AI 상담도 팀에서 구현했습니다. AI 상담은 다른 담당자의 구현 범위입니다.

## 기술과 시스템 구성

| 영역 | 확인한 기술 | 사용 범위 |
| --- | --- | --- |
| 화면 | Vue 3, Pinia, Vue Router, Vite, SCSS | 지도·필터·상세 패널과 사용자 상태 관리 |
| 지도 | Kakao Map | 위치 탐색과 마커 표시 |
| API | Java 21, Spring Boot 3.5, JPA, MyBatis | 사용자 요청 처리와 지도·상세 조회 |
| 데이터 수집 | Spring Batch | 실거래·공매·건축 정보의 적재와 갱신 |
| 저장 | MySQL, 공간 인덱스 | 정규화된 물건·거래 정보와 위치 조회 |

수집 애플리케이션과 사용자 API를 분리했습니다. 배치가 공공 데이터를 정규화해 공통 DB에 적재하고, API는 지도 영역·필터에 맞는 결과와 상세 정보를 반환합니다. 좌표와 건축 정보 보강은 거래 데이터의 일일 갱신과 별도로 다룹니다.

## 설계에서 고려한 점

### 지도 축척에 따라 조회 단위를 나누기

넓은 범위에서도 개별 단지를 모두 표시하면 마커가 겹치고 결과가 과도해집니다. 지도 조회를 개별 단지 마커와 행정구역 집계로 나누고, 마커 응답에는 상한 초과 여부를 함께 전달하도록 구현했습니다.

단순히 결과 일부만 반환하면 사용자는 그 범위의 물건이 전부라고 오해할 수 있습니다. 잘림 여부를 응답에 남겨 화면에서 추가 탐색을 안내할 수 있도록 했습니다. 테스트에는 역전된 경계값 거절, 좌표 범위 검사, 반환 상한과 행정구역 집계가 포함되어 있습니다. 실측 응답시간이나 부하 개선율은 별도로 제시하지 않습니다.

### 데이터 갱신의 범위를 제한하기

지역·기간별 거래를 다시 수집할 때 다른 지역의 단지·좌표·건축 정보를 함께 지우지 않도록 처리 범위를 나눴습니다. 거래는 선택 범위를 교체하고, 파생 단지와 보강 정보는 갱신·추가하는 방식입니다. 이미 얻은 좌표·건축 정보를 매일 다시 조회하는 비용도 피하도록 갱신 작업을 구분했습니다.

## 결과와 한계

데이터 수집부터 지도 탐색, 상세 비교, 관심 목록까지 이어지는 서비스를 구현했습니다. 다만 수집 시점과 원천 기관의 갱신 주기에 따라 정보 차이가 생길 수 있으며, 좌표가 검증되지 않은 단지는 지도 노출에 제약이 있습니다. AI 상담과 조회 정보가 실제 권리 분석이나 입찰 판단을 대신하는 것은 서비스 범위에 포함하지 않습니다.
